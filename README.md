# 国护云｜校学生国旗护卫队社团管理平台

本项目是面向校学生国旗护卫队的独立数字化队务平台，采用 Flask、SQLAlchemy、JWT 与目录文件存储，实现活动执行、装备保障和办公室档案管理。

## 社团与组织背景

校学生国旗护卫队承担校园日常升旗、重要庆典出旗及爱国主义教育等任务。平台按实际协作流程设置三个部门：

- 综合办公室：队务协调、社交媒体入口、文件留档、活动素材审阅与管理。
- 教官部：升旗/出旗/训练项目创建、主教官移交、考勤、表现评分、总结和素材提交。
- 后勤部：设备分类登记、领用归还记录、实时库存及占用冲突提示。

## 角色与权限

- `member`（普通社员）：参与活动与签到、申请设备、提交素材、发帖回复和申请加入部门，不具有后台编辑权限。
- `minister`（部长）：仅拥有所属部门的后台编辑和审批权限，可向本部门普通社员授予最长 90 天的临时后台权限。
- `captain`（队长）：独立于综合办公室、教官部和后勤部，拥有全队管理权限，并兼容原系统管理员接口。

活动项目另设“活动主教官”这一项目级权限。教官部部长可将单个项目移交给任意有效用户，主教官可独立维护该项目的考勤、评分、总结与素材。

## 成员与组织流程

- 新社员在登录页提交注册申请，账号在队长审核通过前不能登录。
- 普通社员申请注销后由队长审核；队长也可直接创建普通社员或部长账户，并对非队长账户执行逻辑注销。逻辑注销保留历史活动、考勤和积分记录。
- 社员加入部门需要队长和目标部门部长分别审核，只有双方均通过后才正式加入。
- 部长或队长可为对应部门普通社员授予带截止时间的临时后台编辑权限，过期自动失效，也可提前撤销。
- 队长交接和部长交接只能由现任账户发起，目标账户本人接受后才生效；部长只能交接给本部门社员。
- 队内论坛采用实名显示，帖子和回复同时显示账户姓名与用户名。

## 已完成的第一版框架

- 全新国护队工作台与三部门入口，支持桌面端和移动端。
- 部门、成员身份及三级角色数据模型。
- 活动项目、项目成员、考勤评分、项目总结、活动素材及办公室审核模型和 API。
- 严格签到时间窗：社员仅能在项目设置的起止时间内本人打卡，结项后保留参与名单、签到方式、打卡时间、评分和考勤汇总。
- 账户积分与流水：项目创建者设置参与积分，项目结项时向有效出勤人员自动发放且每人每项目只发放一次。
- 未开始项目支持修改时间、地点、签到窗口和积分；项目可填写原因后人为终止，并保留终止时间记录。
- 活动课表按周展示未来升旗、出旗和训练安排，已终止项目自动排除。
- 活动项目和设备支持封面图片上传，并在目录列表中直接展示；上传完整保留中文原始文件名，落盘统一使用随机文件名。
- 父子级设备分类树、设备台账、领用归还记录和库存冲突校验。设备支持编辑和删除，并有「正常 / 维修中 / 报废 / 已遗失」四种状态：非正常状态不可领用，报废设备不计入首页在库数量；已有领用历史的设备不允许删除，只能改为报废以保留台账。
- 社媒账号、文件档案、素材审阅队列，社媒账号与档案均支持编辑和删除（删除档案只解除归档关系，文件库中的原始文件保留）。素材提交和档案归档都通过内置的文件库弹窗完成上传与选择，不再需要手填文件 ID，档案和素材均可直接下载。
- 注册/注销审核、部门双审批、临时授权、队长及部长双向交接流程。
- 实名队内论坛，支持发布主题、回复以及本人或队长删除帖子。
- 独立时间中心，汇总活动日程、设备应归还时间、素材待审时间和跨模块操作记录。
- 提供独立的登录鉴权、通用文件上传、文件权限和访问记录能力，个人中心支持自助修改密码。

## 技术栈

- 前端：原生 HTML、CSS、JavaScript 单页应用
- 后端：Python 3.10+、Flask、Flask-SQLAlchemy、Flask-JWT-Extended
- 数据库：本地开发默认 SQLite（免安装），生产部署支持 MySQL 8+
- 鉴权：JWT + bcrypt

## 系统结构

```text
浏览器单页工作台（frontend）
        │ JSON / multipart + JWT
        ▼
Flask 蓝图接口（backend/routes）
  ├─ auth：账户与身份
  ├─ club：活动、设备、办公室业务
  └─ files：通用文件与媒体资源
        │
        ▼
SQLAlchemy 领域模型（backend/models.py）
        │
        ├─ MySQL：业务元数据、权限、分类和记录
        └─ uploads：文件、活动封面和设备图片
```

设备分类使用自关联结构，`equipment_category.parent_id` 指向上一级分类，可以继续扩展多层目录。活动封面保存在 `uploads/covers/activity`，设备图片保存在 `uploads/covers/equipment`，数据库仅保存随机文件名。

## 本地启动

```powershell
cd D:\国护队项目
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt
```

本地预览无需安装 MySQL，初始化脚本会在 `backend/ghd_platform.db` 创建 SQLite 数据库。如需切换到 MySQL，请配置：

```powershell
$env:DB_HOST='127.0.0.1'
$env:DB_BACKEND='mysql'
$env:DB_PORT='3306'
$env:DB_USER='root'
$env:DB_PASS='your_password'
$env:DB_NAME='ghd_platform'
$env:SECRET_KEY='change_me'
$env:JWT_SECRET_KEY='change_me_too'
```

也可以直接设置完整的 `$env:DATABASE_URL`；它的优先级高于上述配置。

首次运行请使用 Python 初始化脚本（不要使用旧版 `sql/init.sql`）：

```powershell
cd backend
..\.venv\Scripts\python.exe init_db.py
..\.venv\Scripts\python.exe app.py
```

保持运行窗口开启，然后在系统浏览器访问 <http://127.0.0.1:5000>。终端中显示的 `0.0.0.0` 是监听地址，不是浏览器访问地址。

停止服务时，在运行 Flask 的终端中按 `Ctrl+C`，不要反复启动多个后台实例。

### 端口冲突与页面无法访问

如果终端显示服务已启动，但 `127.0.0.1:5000` 无法打开，先停止原服务，再使用备用端口：

```powershell
cd D:\国护队项目\backend
..\.venv\Scripts\python.exe -m flask --app app run --host 127.0.0.1 --port 5002
```

随后访问 <http://127.0.0.1:5002>。可使用下面的命令检查 5000–5002 端口是否存在残留监听进程：

```powershell
Get-NetTCPConnection -State Listen |
  Where-Object { $_.LocalPort -in 5000,5001,5002 } |
  Select-Object LocalAddress,LocalPort,OwningProcess
```

通过 `Get-Process -Id <OwningProcess>` 核对进程确实属于本项目后，再使用 `Stop-Process -Id <OwningProcess>` 关闭；不要直接结束未确认用途的 Python 进程。

## 核心接口

| 模块 | 路径前缀 | 说明 |
|---|---|---|
| 认证 | `/api/auth` | 登录、资料、密码、头像 |
| 活动 | `/api/club/activities` | 项目、限时打卡、考勤名单、移交、编辑、终止、总结、素材 |
| 活动课表 | `/api/club/schedule` | 按时间范围查询未来活动安排 |
| 账户积分 | `/api/club/points/my` | 当前积分和参与积分流水 |
| 组织治理 | `/api/governance` | 账户审核、部门双审、临时授权和职务交接 |
| 队内论坛 | `/api/governance/forum` | 实名主题、回复和帖子管理 |
| 后勤 | `/api/club/equipment` | 分类、台账、编辑删除、领用和归还 |
| 办公室 | `/api/club/office` | 社媒、档案（含编辑删除）、素材审阅 |
| 时间中心 | `/api/club/time` | 日程提醒、超期提示和统一操作时间轴 |
| 文件 | `/api/files` | 通用文件上传、授权、下载和预览 |

## 后续迭代建议

当前版本以稳定的数据结构和部门工作流为主。后续适合逐步加入请假审批、训练计划、值班排班、消息通知和学期考评报表，并为文件模块补上独立的文件库页面、分享链接和访问日志查询。设备分类改父级时目前只拦住了「自己当自己的父级」，还没有做多级环检测，构造出 A→B→A 会让 `full_name()` 死循环，需要补上。
